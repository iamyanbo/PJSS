# v1.0.1: empty-support crash fix, verified bit-identical to v1.0 (2026-10-26)

**Bottom line.** v1.0.1 changes one line in each of three modules, so that an empty candidate support no longer
crashes the model. On **13,662 re-run test and benchmark runs**, its answers are **bit-identical** to the stored
frozen-v1.0 records; this covers every stored test archive of the final model, the full dysts archive, hard120 and
every ODEBench run that v1.0 completed. The 742 ODEBench runs that crashed under v1.0 now return an answer, and
v1.0.1 raised **0 exceptions** anywhere.

## The bug

- **Where.** `joint_nd.discover`, `joint_discover.discover` (line ~337) and `joint_colored.discover` (the AR(1)
  path). Each ranks the candidate proposals with `idx = np.array(key)`.
- **What goes wrong.** For the empty proposal, `key == ()`, so `np.array(())` is a float array, and
  `A[:, idx]` raises `IndexError`.
- **When it fires.**
  - every D = 1 call;
  - some short 2-D series: ODEBench id 51 at σ = 2%, and the 21-point lynx–hare series;
  - 3 of 320 ODEBench 3-D runs (Maxwell–Bloch at σ = 5%).
  - It never fired on any stored test archive (see the table below).

## The fix

```python
# v1.0.1: int dtype so that the empty proposal (key == ()) is scored as the all-zero model
# instead of raising IndexError (np.array(()) is float); add() never fits empty supports
idx = np.array(key, dtype=int)
```

- **What the empty proposal now does.** It is scored by the profiled quadratic as the all-zero model: least
  squares with zero columns, residual ‖b‖². If it ranks among the finalists, `add()` skips it, exactly as v1.0
  skips empty supports everywhere else.
- **All-zero equations.** An all-zero equation inside a non-empty model (for example dx/dt = 0 in D = 2) was
  already valid in v1.0 and still is.
- **Why answers cannot change.** In v1.0, an empty key that reached this line always raised. So a run that
  completed never contained one, and its computation is unchanged.
- **Other places checked.**
  - `joint_squeeze.discover_sq` drops proposals with an empty equation (`mask.any(0).all()`) before the same line.
  - Its `ev_pen` only sees the supports of fitted models, which are never empty.
  - `flow_discovery` and `joint_biglib` already used `dtype=int`.
  - All other `A[:, idx]` uses build `idx` with `np.flatnonzero`, which is already an integer array.
- **Not changed.** If every start is empty, `fit_starts` still raises `RuntimeError("no start model fitted")`.
  That is a different, explicit condition: no seed with any term. It never occurred in these runs. Spot checks of
  a constant series and of pure noise, in D = 1 and D = 2, returned valid models.
- **Version number.** `eqdisc.__version__` became 1.0.1 at commit `e4b4b9c`. The md5s are in
  `results_v101/frozen.md5`.
- **Within v1.1.** v1.0.1 is also available inside the v1.1 package as `discover(..., version="1.0.1")`.
  `tests/test_equivalence.py` now tests exactly that path.

starts caches. Job: `results_v101/job.sh`; log: `results_v101/progress.log`. The comparison is
`python benchmarks/v101_compare.py all` (output in `results_v101/compare.md`).

- **What is compared.** Every stored output field of every run, by exact equality (floats as stored in JSON):
  - exact flag, F1, coefficient error, FP/FN;

  - The 742 runs that crashed under v1.0 (372 fit on IC 0, 370 on IC 1) all return an answer under v1.0.1.
  - The earlier crash-patched diagnostic arm (`results_odebench/fit_ic0_emptyfix.json`, D = 1–2, 816 runs) is

## What went wrong along the way

- **pytest missing.** pytest was not installed in the Spark venv, so the first equivalence-test attempt in
  `job.sh` failed at once (rc = 1, nothing run). pytest 9.1.1 was installed, and the test ran after the re-runs
  (`results_v101/job_pytest.sh`).
- **No git on the Spark.** `tests/test_equivalence.py` therefore gained `EQDISC_FROZEN_SRC`, a directory holding
  the frozen files exported with `git archive ac7ab20`. The md5 check against `frozen.md5` is unchanged.

## Results with v1.0.1 where v1.0 crashed

- **ODEBench.** Reconstruction / generalization accuracy rises from 36.8 / 23.3% (v1.0) to **68.3 / 48.9%**, and
  exact recovery on in-library systems from 24.6 to 50.7%. D ≥ 2 numbers are unchanged. Details are in
  `docs/reports/odebench.md`.
- **Lynx–hare raw (21 points).** dx0/dt = 55.3·x0 − 3.33·x0·x1, dx1/dt = 0. It is degenerate, its integration
  diverges, and it is not flagged (gap 9.1). See `docs/reports/real_data.md`.
